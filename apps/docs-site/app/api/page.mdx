# Go API reference

The Go service uses `net/http` method-and-path routing. Unless stated otherwise, the API base is `http://localhost:8080` and application paths are under `/api/v1`. Production deployments should use HTTPS. JSON success responses use `{ "data": ... }`; errors use `{ "error": { "code": "...", "message": "..." } }`. Responses include `X-Request-ID` for support correlation.

| --- | --- | --- | --- |

| POST | `/api/v1/staff/institutions/{institutionID}/claims/{claimID}/review` | Staff in institution | Approve, reject, or request more information |

## Calling the API

```bash
curl --include \
  'http://localhost:8080/api/v1/items/search?q=blue%20backpack&kind=found' \
  -H 'Accept: application/json'
```

A browser app sends the session cookie automatically with `credentials: 'include'`. A signed-in caller may also use `Authorization: Bearer <session-token>` where the client integration supports it. Cookie-authenticated state changes must originate from an allowed browser origin. Do not put tokens in URLs.

```json
{
  "data": [
    {
      "id": "fictional-item-id",
      "institution_id": "fictional-institution-id",
      "institution_name": "Example Campus",
      "category": "Bags",
      "title": "Blue backpack",
      "description": "A blue backpack with a small stitched patch.",
      "location": "Main library area",
      "occurred_on": "2026-01-15",
      "kind": "found",
      "status": "found"
    }
  ]
}
```

All values above are illustrative. Public data is sourced from the safe public projection, not from private report fields.

## Errors and limits

Errors use a stable machine-readable `code` and a concise safe `message`. Common statuses include 400 validation, 401 unauthenticated, 403 unauthorized/origin denied, 404 unavailable or not found, 409 state conflict, 413 body too large, 429 rate limited, and 503 unavailable/not ready. The API caps JSON request bodies at 1 MiB. See [Security and operations](/security) for origin rules, forwarded IP trust, and current rate-limit policy.

For detailed request/response fields and behavior by domain, see [authentication and identity](/api/authentication), [public discovery](/api/discovery), [user actions](/api/user-actions), [institution operations](/api/staff), and [platform administration](/api/platform).
